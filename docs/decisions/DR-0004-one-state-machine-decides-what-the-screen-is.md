# DR-0004: 画面ぜんぶの姿は 1 つの状態機械が決める

Status: Accepted
Date: 2026-09-17

ここに書くのは**なぜそう決めたか / 何を捨てたか**。操作の器は [DR-0003](DR-0003-an-action-is-what-a-key-and-a-button-both-reach.md)、設定の器は [DR-0002](DR-0002-settings-are-sections-tried-before-they-are-kept.md)、色は [DR-0001](DR-0001-colour-is-computed-from-a-few-inputs.md)。

§7 は**裁定の記録**。3 つの問いは 2026-09-18 に解けているので、実装に着手してよい。

## 1. 背景

### 1.1 今、姿はどう決まっているか

画面ぜんぶのうちどの姿で立つかを決めているのは `App.tsx` の 5 つの `if` で、上から順に読まれる。

```
1. registration !== undefined   → 登録の画面 (バー無し)
2. route.at === "settings"      → 設定の画面 (バー無し)
3. needsSignIn                  → バー + 認証の画面
4. !listed                      → バー + 本文なし (言葉があれば言葉だけ)
5. それ以外                      → バー + workspace (Shell)
```

読まれている 5 つは互いを知らない独立した signal で、書く所も別々にある。

| 読むもの | 型 | 置き場 | 書く所 |
|---|---|---|---|
| `registration` | `Registration \| undefined` | `state.ts` | 登録 URL の fragment が届いた時 / 登録が済んだ時 |
| `route` | `Route` | `state.ts` | URL |
| `needsSignIn` | `boolean` | `auth/session.ts` | `signIn` の失敗、`authRequired` |
| `listed` | `boolean` | `state.ts` | `peers` の snapshot が届いた時、`disconnect` |
| — (姿には出てこない) | | | |
| `wanted` | `boolean` | `state.ts` | 人が接続 / 切断を押した時、`resume` |
| `status` | `ConnectionStatus` | `state.ts` | `Connection` が socket の各段で |
| `generationWarning` | `string \| undefined` | `state.ts` | `generationMismatch` |
| `needsRegistration` | `boolean` | `auth/session.ts` | `signIn` が declined で返った時 |

### 1.2 何が起きているか

**姿の組み合わせを点検する場所が無い**。5 つの `if` の順番が、書いた人の意図ではなく副作用として裁定を作っている。

- `registration !== undefined` が最初なので、**接続後に登録 URL を開くと workspace ごと消える**。読んでいた transcript は裏に残っているが、画面には登録の用紙しか出ない。
- `route.at === "settings"` が `needsSignIn` より先なので、**未認証のまま設定に入れる**。issue の裁定 (「設定は接続後のみ」) と食い違っているが、食い違っていることがコードのどこにも出ていない。
- 設定と登録では帯ごと画面が置き換わる。これは DR-0003 §2.2 が既に食い違いとして記録している。

**同じ状態の見せ方が 2 か所にある**。契約の世代の食い違い (`generationWarning`) は `Disconnected.tsx` と `Shell.tsx` の両方に同じ文言が書かれている。同じ 1 つの事実に 2 つの見せ方があり、揃えているものが無い。

**「繋がっているか」が 4 つに散っている**。`wanted` (人の意図) / `status` (socket が今していること) / `listed` (一度でも聞いたか) / `hello` (名乗りを受け取ったか) のどれ 1 つも、単独では「今どの姿で立つか」を言えない。組み合わせの意味は `App.tsx`・`Stale`・`ConnectionBar` に分かれて書かれている。

### 1.3 これから触るものが全部この上に乗る

- 接続バーの作り直し ([issue](../issue/2026-09-17-connection-bar-is-not-a-header-after-connect.md)) は「接続前は主役、接続後は小部品」を言う。**どこからが接続後か**を言う場所が要る。
- 設定は接続後のみ。同上。
- 登録 → 認証 → 接続の流れは今 3 つの signal に分かれている。
- DR-0003 のスコープの木の根は「未接続」と「接続後」で、**根がどちらに立つかは今どこにも書いていない**。
- 契約世代のずれ・再接続・世代の食い違いの後始末。

[daemon リポの research](https://github.com/kawaz/ccmsg/blob/main/docs/research/2026-09-17-vlmkit-and-agent-ui-article.md) が「記事の処方のうち ccmsg-webui に無い唯一の骨格」として名指したのがこれ。ccmsg-webui は Passive View も Root を頂点とする木も内から外へのバブルも既に持っていて (DR-0003)、持っていないのは**全体の状態と遷移を一望する 1 枚**だけ。

## 2. 決定

### 2.1 姿は 1 つの値で、`phase` と綴る

画面ぜんぶのうちどの姿で立つかは、`phase` 1 本が答える。値は 7 つ。

**規則と配線は分かれている**: 姿を導く規則 (`phaseOf`) が `src/phase.ts` に、材料の signal を渡す `computed` が `src/state.ts` にある。1 つの file に収めないのは §2.9 の test のためで、`state.ts` は読み込みだけでブラウザを要るので、それを連れてくる module は test から呼べない。

| 値 | 何か | 木の根 (DR-0003 §2.2) |
|---|---|---|
| `offline` | 住所を述べる所があり、繋いでいない | 未接続 |
| `registering` | 登録 URL を開いた | 未接続 |
| `authenticating` | passkey を求める所に居る | 未接続 |
| `connecting` | socket を開けている (名乗りの途中も含む) | 未接続 |
| `receiving` | socket は開いた、一覧の snapshot がまだ | 未接続 |
| `live` | 一覧があり、話し相手が居る | 接続後 |
| `stale` | 一覧があり、話し相手が居ない | 接続後 |

**「未接続」は「一覧がまだ立っていない」の意**。socket が開いている `receiving` も未接続に入る — 根が分けているのは回線の有無ではなく**画面に本体が立っているか**で、DR-0003 §2.2 が未接続の子に「一覧を聞く前 (Disconnected)」を置いているのと同じ線。

**`stale` を `live` と分けるのは、出ている行がいつのものかが違うから**。一度立った本体は、回線が切れても認証が切れても消さない。`stale` でも本体は出たままで、古いことは印が言う。

**`stale` はなぜ切れているかを分けない**。回線が届かないのか、refresh token が切れて向こうが繋がせないのかは `statusDetail` が既に答える従属の事実で、姿としては同じ (本体 + 印) だから。違うのは**人に何を頼むか**で、認証が切れている時だけ passkey の再認証を重ねる (§2.4)。

**契約の世代の食い違いを姿にしない**。世代がずれても、今画面に出ている内容が読む価値を失うわけではない — 読む価値があるかを決めるのは人であって、この画面ではない。ずれていることは再読み込みのボタンの色が変わる形で伝え、押すかどうかは人が選ぶ (§2.4)。

**切れている間と再接続中は分けない**。姿が同じ (本体 + 印) で、印の中の語は `status` が既に答えている (`closed` なら「接続が切れました」、`connecting` なら「接続し直しています」)。既存フィールドが答えられる問いには何も足さない。

**「切断」は人が押す操作の語で、起きたことの語ではない** (§2.6)。回線が落ちた・届かない・許可が切れたのは `phase` と `status` が言う出来事なので、画面に出す語も出来事の側にする (「接続が切れました」「接続し直しています」)。同じ文字を操作と状態の両方に使うと、切れたのを自分がやったのだと読む人が出る。

**住所が無い状態 (`endpoint === undefined`) を分けない**。姿は `offline` と同じ (バーがあり、本体が無い) で、違うのは接続のアクションが今できるかだけ。それは `endpoint` を読めば言えるので、姿を割る理由が無い。

### 2.2 `phase` は導出であって、代入されるものではない

`phase` は `computed` で、既存の signal から導く。

```
registering    registration !== undefined
authenticating needsSignIn
live           listed かつ status === "open"
stale          listed
receiving      status === "open" または "greeting"
connecting     wanted
offline        それ以外
```

遷移を `send` で起こして `phase` に代入する形にはしない。**引き金はどれも既存の signal の変化そのもの**なので、代入すると同じ事実が 2 か所に住むことになり、片方だけが古くなる余地ができる。`computed` なら定義が 1 つで、遷移表 (§2.3) は**この式の読み方**になる。

上の並びは**上から順に読む**。これは §1.2 が問題にした「順番が裁定を作る」形と同じに見えるが、違うのは**順番そのものが裁定として 1 か所に書いてある**ことで、§2.3 の遷移表と §2.4 の姿の表がその裁定を点検できる形にしている。順番に意味があるのは 2 つだけ:

- `registering` が `live` より先 — 登録 URL を開くのは人が起こしたページの読み込みで、置き換わるのが正しい (§2.4、§7 Q3)。
- `live` / `stale` が `receiving` / `connecting` より先 — 一度聞いた一覧があるなら、回線が今どうであれ本体は立つ。

### 2.3 遷移は 1 つの表に書く

「何が起きたら移るか」を 1 枚にする。左の列が今の姿、真ん中が起きたこと、右が次の姿。**空欄が見落とし**として読める形にすることが表の目的で、網羅していることに価値がある。

| 今 | 起きたこと | 次 |
|---|---|---|
| (読み込み) | fragment に登録 URL がある | `registering` |
| (読み込み) | refresh cookie で session が取れた (`resume`) | `connecting` |
| (読み込み) | session が無い | `offline` |
| どれでも | 登録 URL の fragment が届いた (`hashchange`) | `registering` — 読んでいたものを置き換える (§2.4) |
| どれでも | 契約の世代が食い違った (`generationMismatch`) | 姿は変わらない。再読み込みのボタンの色が変わる (§2.4) |
| `offline` | 接続を押し、session を持っていた | `connecting` |
| `offline` | 接続を押し、session が無かった | `authenticating` |
| `offline` | 住所を述べ直した | `offline` |
| `registering` | 登録が済んだ (`completeRegistration`) | `connecting` |
| `registering` | やめた (`dismissRegistration`) | `resume` の答え (`connecting` か `offline`) |
| `registering` | この画面では登録できない URL だった | `offline` (言葉を添える) |
| `authenticating` | passkey が通った | `connecting` |
| `authenticating` | passkey を断られた (declined) | `authenticating` (登録の案内を添える) |
| `authenticating` | それ以外の失敗 | `authenticating` (instance の言葉を添える) |
| `connecting` | socket が開き、名乗りが通った | `receiving` |
| `connecting` | 提示するものが無かった (`authRequired`) | `authenticating` |
| `connecting` | 届かない / 拒まれた | `connecting` (退がりながら再試行) |
| `receiving` | `peers` の snapshot が届いた | `live` |
| `receiving` | socket が閉じた | `connecting` (一覧をまだ持っていないので `stale` にはならない) |
| `receiving` | `authRequired` | `authenticating` |
| `live` | socket が閉じた | `stale` |
| `stale` | socket が開き直り、snapshot が届いた | `live` |
| `live` / `stale` | `authRequired` / 繋ぎ直せない (`auth_invalid`) | `stale` のまま。passkey の再認証を重ねる (§2.4) |
| `live` / `stale` | 回線が届かない (`unreachable`) | `stale` のまま。**passkey は頼まない** — 退がりながら繋ぎ直し、回線が戻れば自分で戻る |
| `live` / `stale` | 重ねた再認証が通った | `connecting` を経て `live` (画面はそのまま) |
| `live` / `stale` | 重ねた再認証が断られた | `stale` のまま (言葉を添える)。頼みは残るか、状態の印から出し直せる |
| `live` / `stale` | 再認証の頼みを閉じた | `stale` のまま。許可が切れている事実は下りない (§2.4) |
| `live` / `stale` | 人が切断を押した (= この端末から降りる、`signOut`) | `offline` (§2.6。頁を立て直すので、そこからの読み込みが `offline` を出す) |
| `live` / `stale` | 人が住所を述べ直した (`setEndpoint`) | `offline` |

**回線が無いことを「許可が切れた」と読まない**。提示するものが無い時、それが「refresh が届かなかった」のか「向こうが断った」のかは分けて運ぶ (`unreachable` / `auth_invalid`) — 分けないと、電波の悪い所で token の期限が切れた人が、許可は切れていないのに passkey を迫られる。届かない時は接続を止めず、退がりながら掛け直す。

**重ねた再認証が断られても、一覧は捨てない**。人が passkey の求めを取り消すのは「今はやらない」であって、読んでいたものを捨ててよいという意思ではない。だから断られた時に `authenticating` を言う材料 (`needsSignIn`) を立てない — 規則の側では認証が一覧より先に読まれる (§2.2) ので、立てた瞬間に画面が消える。

**一覧を持っている姿では `authRequired` で画面を捨てない**。許可が向こうで切れたという事実は同じでも、それを理由に読んでいたものを消す必要は無い — 人に頼むのは passkey をもう一度だけで、通ればその場で繋ぎ直る。一覧をまだ持っていない `connecting` / `receiving` でだけ `authenticating` へ行くのは、捨てるものがそこに無いから。

### 2.4 姿ごとに、何が見えるか

接続バーと設定の置き場は issue の裁定 (接続前の主役 / 接続後の小部品、設定は接続後のみ) をそのまま姿の列に割ったもの。

| 姿 | 接続バー | 本文 | 重なるもの | 設定 | 再読み込み |
|---|---|---|---|---|---|
| `offline` | 主役 (住所 + 接続)、中央 | 無し (言葉があれば言葉だけ) | — | 入れない | ボタン |
| `registering` | 主役、中央 | 登録の用紙 | — | 入れない | ボタン |
| `authenticating` | 主役、中央 | passkey の画面 | — | 入れない | ボタン |
| `connecting` | 主役、中央 (題が「接続中…」) | 無し | — | 入れない | ボタン |
| `receiving` | 主役、中央 (題が「接続済み」) | 無し | — | 入れない | ボタン |
| `live` | 細いツールバー (状態の印 + 頁を動かす手) | workspace | — | 入れる | ボタン |
| `stale` | 同上 | workspace (最後に聞いた内容) | 回線なら知らせ、認証なら再認証のダイアログ | 入れる | ボタン |

**トップ (未接続の 5 つ) は中央に置く**。用件が「繋ぐ」しか無い画面なので、上端に貼り付けて下を空けておく理由が無い。縦は `dvh` を基準に、**余りがある時だけ**中央へ寄せる (`justify-content: safe center`) — 余りが無い時に中央のままだと、狭い画面でソフトキーボードが出た時に押す所が画面の外へ出て、触れなくなる。登録 URL を開いた画面 (生死を確かめている間・登録の用紙・使えない URL の知らせ) も同じトップの仲間として同じ置き方にする: どれも用件が 1 つで、次の一手がその場にある画面。

**トップには状態の印を置かない**。そこで取りうる状態は「まだ繋いでいない」しか無く、1 つの値しか取らない印は出ていること自体が何も言わない。繋ぎに行っている間だけは何かが起きているので、それは**押したボタンが題で言う** (「接続中…」「hello 送信中…」) — 押せない間の題がそのまま今の状態になるので、印を別に置かずに済む。接続後の印 (`StatusMark`) は残る: そちらは繋ぎ直している最中も許可が切れたことも言う。

**画面に出ているものを、この画面の判断で隠したり読み込み直したりしない**。今出ている内容が今いちばん大事なことは大いにあり、それを捨てる判断は人のもの。だから終端の姿を持たず、世代のずれも「押せる印」までで止める。

**登録 URL を開くことはこの画面の判断ではない**。接続中に `#enroll=` 付きの URL を開いたら `registering` に**置き換わる** — それはページの読み込みと同じ出来事で、人が起こしたこと。捨てているように見えるものは捨てていない: 一覧も transcript も instance が持っていて、読み込み直すか繋ぎ直せば戻る。だから重ねる形を採らず、姿として持つ (§7 Q3)。**ccmsg の中から登録 URL へリンクを張る時は別のタブで開く** — こちらが起こす遷移で読んでいたものを置き換えないための、リンクを書く側の約束。

**再読み込みのボタンはどの姿にも常に置く**。ホーム画面に追加した PWA にはブラウザの再読み込みが無いので、これが無いと人は読み込み直す手段を持たない。**契約の世代が食い違ったら、このボタンの色が変わる** — 姿でも帯でもなく、既にある常設の押す所の見た目が変わるだけ。

**認証が切れて繋ぎ直せない時は、再読み込みより目立つ形で言う**。画面の中央に passkey の再認証のダイアログを重ねるか、画面内に重ねる知らせで導線を出す (どちらにするかは実装時に決めてよい。ダイアログにする場合は DR-0003 の「重なるもの」の節をそのまま使う)。通ればその場で繋ぎ直り、後ろの workspace は最初から動かない。

**その頼みは閉じられる**。ダイアログにすると後ろが丸ごと不活になるので、閉じられないと §2.5 の「読むことはできる」が成り立たない — 切断も読み込み直しも押せず、passkey が通らない端末 (認証器を失った、別の人の端末、所有を外された) はそこから出る道を持たなくなる。閉じても許可が切れている事実は下ろさず、**状態の印がそのまま出し直す入口になる** — 頼みを出し直すためだけの押す所を新しく増やさない。

**接続後の道は、スマホのステータスバーのような細いツールバー**。載るのは 5 つだけ:

| 載るもの | 何か |
|---|---|
| 接続状態の印 (`StatusMark`) | 繋ぎ直している最中か、許可が切れたか。許可が切れている間は押す所になる |
| 戻る (`app.back`) | `history.back()`。履歴の手前が無ければ押せない |
| 進む (`app.forward`) | `history.forward()`。一度も戻っていなければ押せない |
| 読み込み直す (`app.reload`) | 常設。契約の世代が食い違ったら色が変わる |
| ハンバーガー | 下の行き先と操作を畳んだ所 |

**戻る / 進む / 読み込み直しをこの画面が持つ理由は、ブラウザの chrome が無い場面があるから** — ホーム画面に追加した PWA や iPad の全画面には、戻る手も読み込み直す手も画面に無い。端末によって在ったり無ったりする道具は当てにできないので、この画面が自分で持つ。

**ツールバーは絵だけを並べる**。横に文字を並べる幅が無いので、題は `aria-label` と tooltip に出す — アクションの題は 1 か所 (catalogue) から出たままで、読み上げにも指にも届く (DR-0003 §2.4)。

**ハンバーガーの中は、行き先と、誤って押されると困るもの**: 一覧の出し入れ、使用量 (上流に問題がある時はその言葉を行に添える)、アカウント、設定、切断。切断は誤って押されると取り返しが付かず (§2.6)、行き先は開きに行く時にしか要らない。使用量を外に出さないのは、ツールバーが絵だけになって**状態の言葉を置く場所が無い**から — 言葉を運べるのはメニューの行の側になった。

**詳しい接続の情報 (instance、契約の版、token の期限、credential の webui、誰として繋がっているか) は接続バーの役目ではない**。接続後のグローバルな状態の画面と、セッションの状態の画面に置く。バーが持つのは「今どうなっているか」を 1 つの印で言うことだけ。

### 2.5 姿ごとに、何ができるか

DR-0003 の木の根がどちらに立つかは `phase` が答える。根が立てば、その下の節は木の形どおりに立つ。

| 姿 | 立つ根 | できること |
|---|---|---|
| `offline` | 未接続 | 住所を述べる / 接続を始める (住所がある時) / 読み込み直す |
| `registering` | 未接続 > 登録 | 登録する (6 桁が揃った時) / やめる / 読み込み直す |
| `authenticating` | 未接続 > 認証 | passkey で認証する (= 接続を始めるのと同じアクション) / 読み込み直す |
| `connecting` | 未接続 | 住所を述べる (述べ直せば `offline` へ) / 読み込み直す |
| `receiving` | 未接続 | 同上 |
| `live` | 接続後 | workspace のすべて / 設定 / 切断 (= 降りる) / 読み込み直す |
| `stale` | 接続後 | 読むことはできる。instance に頼むもの (送る・終了・開く) は断られる。認証が切れているなら passkey で繋ぎ直す |

**`stale` で 1 つ 1 つの操作が断られる判定は、この状態機械に吸収しない**。`phase` が答えるのは姿と根であって、個々のアクションの「できるか」は今どおりアクション側が持つ (DR-0003 §2.1) — 断り方は操作ごとに違う (送れない理由を言う `messageSendRefusal` と、単に押せなくなるものは同じではない)。

**設定はどの未接続の姿からも入れない**。言語も light / dark もそこには置かない — 繋がる前の人に出す設定は、出した分だけ「繋ぐ」以外の道を増やす。多言語そのものを世に出す時に、置き場ごと考え直す (DR-0003 §2.2 の木からも未接続の設定の節を落とす)。

### 2.6 画面に出す切り方は 1 つ (= 降りること)

**このシステムは接続 = 認証**なので、繋がっていない状態と降りている状態を人が区別する意味が無い。だから webui が出す操作は「切断」1 つで、意味は下の表のとおり。

| | 何をするか | 後に残るもの | 戻り方 |
|---|---|---|---|
| **切断** | 契約の `auth.signout` で token family の失効を頼み (応答が refresh cookie を期限切れにする)、**この origin の `ccmsg.` のキーを全部消し、トップを読み込み直す** | 既定では何も残らない。設定を 1 つ入れれば人の好みだけ残る | passkey からやり直す |

**socket を閉じるだけの切り方を画面に出さない**。2 つ並べると、ちょっと切りたいだけの人が毎回 passkey をやり直すか、降りたつもりの人の cookie が残るかのどちらかになる — 前者は「席を外す」に高すぎる代償で、後者は降りたことにならない。1 つにするなら降りる側に倒す: 席を外すだけなら頁を閉じれば済み、cookie が残っていて困るのは降りたい人の方。

**意図しない切断はこの操作ではない**。回線が落ちただけなら印が言い、認証が切れていれば再認証の頼みが重なる (§2.4) — どちらも姿は `stale` のままで、人に降りることを求めない。**プロトコルの語はそのまま** (`auth.signout`)。画面に出す語が 1 つになっただけで、契約の側で失効を頼む操作の名前が変わるわけではない。

**降りるは向こうに頼む**。契約の `auth.signout` が family を失効させ、その応答が refresh cookie を期限切れにする — cookie は HttpOnly なのでこの画面からは消せず、手元だけ消しても cookie を持った別のタブが繋がり続ける (契約 DR-0030 §5)。

**既定は全部消す**。`ccmsg.` で始まるこの origin のキーを、好みも含めて 1 つ残らず消す — 降りるのは「この端末から降りる」なので、既定が「降りた跡が残る」形をしているべきではない。好みを消しても取り返しがつかないのは今だけで、設定がユーザの record としてサーバに載れば (契約 DR-0030 §6)、次に入り直した人の好みは向こうから戻ってくる。

**向こうが答えなくても手元は消す**。`auth.signout` が届かなくても、降りると決めた人の端末に跡が残る方が悪い — family が生きていることは次に繋いだ時にまた降りれば済む。届かなかったことは 1 行の言葉にして残し、そこで止めない (別のタブがまだ繋がることの説明が付かなくなるため)。

**降りるは読み込み直しで終わる**。手元から消すのは localStorage に書いてあるものだけではない — 留めたセッションも、絞り込みも、選んでいた 1 通も、読み込みの時に読んだ写しとしてメモリに立っている。同じタブで次の人が入った時にそれが残っていれば、一覧は前の人の仕事で始まる。**消して回る一覧を持たない**のは名前の規律と同じ理由で (一覧はキーが増えた時にそれだけが古くなる)、頁を立て直せば残るのは localStorage に残したものだけになる。好みが戻るのは設定を入れた時だけで、それは残ったものを読み直した結果。届かなかったという 1 行はその読み込みをまたぐ必要があるので、URL の fragment で渡して読んだ所で消す — 手元に何も残さないと決めた後に残せる場所は、そこしかない。

**残したい人は設定で残す**。「切断時にローカルの設定を残す」を設定の 1 項として持つ (DR-0002 の section の 1 つ、**既定 off**)。入れた時に残るのは**人の好みのキー**で、名前に**ユーザ・instance・sid のどれも含まない**もの (`ccmsg.theme`、`ccmsg.timeline.display:<main|sub>`) がそれにあたる。**認証・接続・セッションに属するキーはこの設定でも残らない** — 残す理由が「選び直すのが面倒」である間は好みにしか当てはまらず、token も書きかけも繋ぎ先も、降りた端末に残す理由が無い (範囲の正本は DESIGN の「localStorage のキー規律」)。

**取り返しが付かない側なので、押したら一度確かめる** (DR-0003 §2.3 の `destructive`、§2.8 の確認)。そして**常時露出させない** — 誤って押されて困るものを、見ている最中に何度も押すもの (一覧の出し入れ・読み込み直し) と同じ列に並べない (§2.4)。

### 2.7 未接続で接続後の URL に来たら

URL はその人が受け取ったもので、この画面が勝手に書き換えてよいものではない。だから**まず繋ぎに行き、繋げた時はその URL の画面を開く**。繋げない時だけ、URL を `/` に戻して接続前のトップを出す。

**ただし URL と画面を捨てるのは「一度も認証したことがない端末」だけ**。判定は `localStorage` に憶えた住所があるかで、無ければこの端末はまだ誰のものでもない。あるなら — 回線が届かないだけでも、refresh token が切れていても — **URL も画面もそのまま**で、§2.4 のとおり再認証か再接続の導線を出す。

| 来たとき | どうなるか |
|---|---|
| 繋げた | その URL の画面 (`live`) |
| 繋げない、憶えた住所が無い | `/` へ書き換え、`offline` |
| 繋げない、憶えた住所がある | URL はそのまま。姿は `offline` / `stale` のいずれか、導線を出して待つ |

### 2.8 吸収されるもの、残るもの

| 今あるもの | どうなるか |
|---|---|
| `registration` | 残る。中身 (誰を・どの instance に登録するか) は登録の画面が読む。**姿を決めるためには読まれなくなる** |
| `needsSignIn` | 残る。**材料としてだけ** — `phase` が `computed` である以上、`authenticating` を言う signal が 1 つ要る。画面からは 1 つも読まれなくなり (§2.9 の test が守る)、`authenticating` であることと同義の値が 2 つある状態は消える |
| `needsRegistration` | 残る。`authenticating` の中で「登録の案内を添えるか」を言う従属フィールド |
| `listed` | 残る。`live` / `stale` と `receiving` を分ける導出元 |
| `status` | 残る。socket が今していること。主語が違う (socket の話で、画面の話ではない) |
| `statusDetail` | 残る。`stale` の理由 (回線か認証か) を言い、§2.4 の重なるものを選ぶ |
| `wanted` | 残る。人の意図。`offline` と `connecting` を分ける導出元 |
| `generationWarning` | 残る。姿の導出には使わず、**再読み込みのボタンの色と、その説明の言葉**になる |
| `terminalsListed` / `listSettled` | 残る。姿ではなく**中身が揃ったか**の話 (空の一覧を出さないため、`data-settled` のため) |
| `hello` / `subject` / `connectionExpiresAt` | 残る。接続後の詳しい情報の中身 |
| `endpoint` | 残る。人が述べる住所。どの未接続の姿でも編集できる。`localStorage` にあるかが §2.7 の判定 |
| `route` | 残る。**接続後のどの画面か**だけを言う。`settings` が姿を横取りすることはなくなる (§2.7) |

### 2.9 `App.tsx` は姿を読んで選ぶだけ

```
switch (phase.value) { ... }
```

**`App.tsx` 以外は `listed` / `registration` / `status` を読んで姿を決めない**。読んでよいのは中身を出す側 (帯が `status` を読んで語を選ぶ、一覧が `listSettled` を読んで空かどうかを言う) だけ。

これを文章の禁止だけにしない。**`src/ui/` のうち `App.tsx` 以外が姿を決める signal を import していないことを検査する test を置く** — この設計の核は「姿を決める場所が 1 つ」という**持たない**形をしているので、2 か所目を足す変更は局所的には改善に見え、文章では止まらない。

## 3. 名前

`phase` と綴るのは、**答えるのが「今どの段に居るか」だから**。7 つのうち 5 つは登録 → 認証 → 接続 → 受け取りの段で、`live` / `stale` も「一覧を得た後のどちらの段か」と読める。

## 4. 不採用

| 採らなかったもの | なぜ |
|---|---|
| **今の `if` の並びのまま** | 姿を決める条件が 5 つの独立した signal の優先順に散り、組み合わせの正当性を点検する場所が無い。登録が workspace を隠すことも、設定が認証より先に効くことも、意図した裁定ではなく順番の副作用 (§1.2) |
| **画面ごとに状態を持つ** | 世代の食い違いが `Disconnected` と `Shell` の 2 か所に同じ文言で書かれている今の形がその帰結。同じ状態の見せ方が 2 か所に分かれると、片方だけが古くなる |
| **XState 等の状態機械ライブラリ** | ライブラリが解く問題 (階層状態、並行領域、遅延イベント、actor 間の通信) が、この 8 状態では起きていない。導入すると遷移が「既存 signal の変化を見て `send` を呼ぶ層」になり、既に signal が持っている引き金を二重に持つ。`computed` 1 本で足りる所に、走る仕組みを増やす理由が無い |
| **`phase` を `signal` にして遷移で代入する** | 引き金はどれも既存 signal の変化なので、代入すると同じ事実が 2 か所に住む。遷移を書き忘れた経路では姿が固まったまま動かなくなり、しかもその失敗は画面を見るまで分からない (§2.2) |
| **`ConnectionStatus` に値を足して 1 つの enum にする** | socket が今していることと、画面が今どの姿かは主語が違う。`connection.ts` は契約と socket だけを知っていて、一覧を受け取ったかも登録 URL が来たかも知らないし、知るべきでない |
| **切断中と再接続中を別の姿にする** | 姿が同じ (本体 + 帯) で、違うのは帯の中の語だけ。それは `status` が既に答えている。姿を割ると、同じ見た目を 2 つの値が指すことになる |
| **住所の無い状態を別の姿にする** | 姿は `offline` と同じで、違うのは接続のアクションが今できるかだけ。それは `endpoint` を読めば言える |
| **`stale` で本体を消す (接続が切れたら画面も空にする)** | 電波の悪い所を歩いた人の画面が毎回空になる。持ち歩いて読む道具としては失いすぎで、最後に聞いた内容には次の snapshot まで読む価値がある (`state.ts` の `status`) |
| **契約の世代ずれを終端の姿にする (`outdated`)** | 画面に出ているものをこちらの都合で隠すことになる。世代がずれても、読んでいた transcript の価値は変わらない — 読み込み直すかは人が決めることなので、決めるための印 (ボタンの色) までを画面の役目にする (§2.4) |
| **世代がずれたら自動で読み込み直す** | 同じ理由で、しかもこちらの方が強い。書きかけも読んでいた場所も断りなく消える |
| **世代ずれを帯で言う** | 常設の再読み込みのボタンが既にあり、その色を変えれば同じことが言える。帯を出すと、押す所が 2 つになり、場所も取る |
| **再読み込みをブラウザに任せる** | ホーム画面に追加した PWA にはブラウザの UI が無い。読み込み直す手段が端末によって在ったり無かったりする |
| **認証が切れたら `authenticating` へ戻す** | 一覧を持っている姿では、読んでいたものを捨てる理由が無い。要るのは passkey をもう一度だけで、それは姿を替えずに重ねられる (§2.4) |
| **繋がらない時はいつも URL を捨ててトップへ戻す** | 受け取ったリンクが一度の通信の失敗で失われる。捨ててよいのは、まだ誰のものでもない端末 (憶えた住所が無い) だけ (§2.7) |
| **接続中に登録 URL が来たら workspace に重ねる** | 重ねる理由は「読んでいたものを捨てない」だが、登録 URL を開くのは人が起こしたページの読み込みで、こちらの判断ではない。しかも捨てているものが無い — 一覧も transcript も instance が持っていて、読み込み直せば戻る。無い損失のために、姿を 1 つ減らして重なりを 1 つ増やすことになる (§2.4) |
| **socket を閉じるだけの切断を、降りることと別に画面へ出す** | 接続 = 認証のこのシステムでは、繋がっていないことと降りていることを人が区別する意味が無い。2 つ並べると、語の違い (切断 / ログアウト) から人が結果の違いを読み取れないまま、片方が「跡が残る切り方」になる。席を外すだけなら頁を閉じれば済む (§2.6) |
| **未接続にも言語と light / dark の切替を置く** | 繋ぐ前の画面に「繋ぐ」以外の道を増やす。多言語はまだ世に出しておらず、置き場は出す時に決めた方が、その時の要求に合う所へ置ける |
| **綴りを `screen` にする** | `route` と紛らわしい。`settings` は URL が名指す所であって姿ではないのに、`screen` と綴ると同じ種類のものに見える |
| **綴りを `appState` にする** | 何を答える値なのかが読めない。`app` も `state` もこの画面では何にでも付く語 |
| **綴りを `standing` にする** | `runs.ts` の `runStanding` (run の立ち位置) と衝突する。同じ語が 2 つの別のものを指す |

## 5. 帰結

- `App.tsx` が `switch` 1 つになり、姿の一覧が読んで分かる。
- DR-0003 の木の根が `phase` を読むので、**木と姿がずれない**。根が立つ条件を木の側で別に決める必要が無い。
- 接続バーの作り直しが「`live` / `stale` では小部品」という 1 行の判断になる。設定が接続後のみ、も 1 か所で言える。
- 世代の食い違いが**常設の再読み込みのボタン 1 つの見た目**になるので、2 か所に同じ文言を書かなくなる。
- 新しい姿を足す時の設計作業が「遷移表に行を足す」になり、**見落としが表の空欄として見える**。今は見落としがどこにも現れない。
- `needsSignIn` が消える。認証の画面が立っていることと「認証が要る」が別の値だったのをやめる。
- **一度立った画面を、この画面の都合で壊す経路が無くなる**。捨てるのは人が押した時 (切断 / 再読み込み) と、まだ誰のものでもない端末の場合だけ (§2.7)。
- 逆に、**`phase` を読まずに `status` / `listed` を直接読む画面が 1 つでも残ると効き目が薄れる**。§2.9 の test がその歯止めで、この DR で唯一の「増やさない」の形をした核。
- 状態が 7 つに収まっているのは今の画面がそうだからで、姿が増えれば表も増える。表が 20 行を超えたら、それは軸が 2 つ混ざっている合図として読む (`design-spec/state-modeling` 8)。

## 6. 前提

| 前提 | 満たさない場合 |
|---|---|
| 姿を決める引き金が、すべて既に signal として在る | 在らないものが出たら `phase` の導出に足す。足せないもの (DOM に聞かないと分からない類) が出たら、`computed` を諦めるのではなく**その事実を signal にする所**から考える (DR-0003 §2.2 の「判定源はアプリ側の状態」と同じ線) |
| 一度に立つ姿は 1 つ | 2 つ同時に立てたくなったら、片方は姿ではなく**姿に重なるもの** (帯・トースト・ダイアログ) で、そちらは DR-0003 の木の節として持つ |
| 接続先は 1 つ | 複数 instance へ同時に繋ぐ形になれば `phase` は instance ごとの値になり、画面ぜんぶの姿はその集約になる。今は mesh の向こう側を 1 つの instance 越しに見る形なので、繋いでいる先は 1 つ |

| Q5 | ログアウトで向こうに何を頼むか | **(a) 契約の `auth.signout`**。token family を失効させ、応答が refresh cookie を期限切れにする | 失効の単位は family — この credential だけを失効させても、同じ人の他のタブが持つ token は生きたまま。cookie は HttpOnly でこの画面からは消せないので、期限切れにできるのは向こうの応答だけ (契約 DR-0030 §5) |
| Q6 | ログアウトで人の好みを消すか | **既定は消す**。`ccmsg.` の付くこの origin のキーを全部消し、「切断時にローカルの設定を残す」を設定の 1 項 (既定 off) として持つ。残せるのは人の好みのキー = 名前にユーザ・instance・sid のどれも含まないものだけ (§2.6) | ログアウトは「この端末から降りる」で、降りた跡が既定で残るのはおかしい。好みを失うことが取り返しのつかない損失なのは、設定がまだこの端末にしか無い今だけ — ユーザの record としてサーバに載れば入り直した時に戻る (契約 DR-0030 §6)。残したい人は居るので設定にはするが、既定を「残す」にすると、端末を手放す人が明示的に外す操作を要求されることになる |
| Q7 (09-19) | 切断とログアウトを画面でどう出すか | **1 つに統合する**。webui 上の操作は「切断」1 つで、意味は従来のログアウト (`auth.signout` + ローカル消去 + 読み込み直し)。`destructive` の印を持ち、ハンバーガーの中に畳む | このシステムは接続 = 認証なので、繋がっていない状態と降りている状態を人が区別する意味が無い。2 つ並べる方が、語から結果の違いを読み取れないまま片方に跡が残る (§2.6) |
| Q8 (09-19) | 接続後の道に何を載せるか | **細いツールバー 5 つ** (状態の印 / 戻る / 進む / 読み込み直す / ハンバーガー)。絵だけを並べ、題は読み上げと tooltip。行き先と切断と一覧の出し入れはハンバーガーの中 | PWA や全画面ではブラウザの chrome が無く、戻る手も読み込み直す手も画面に無い。横幅に文字を並べる余地が無いので、状態の言葉はメニューの行へ移す (§2.4) |
| Q9 (09-19) | トップ (未接続) の置き方 | **中央** (余りがある時だけ寄せる)。状態の印は置かず、繋ぎに行っている間は接続ボタンの題が言う | 用件が「繋ぐ」しか無い画面で、上端に貼る理由が無い。取りうる状態が 1 つしか無い印は、出ていること自体が何も言わない (§2.4) |
